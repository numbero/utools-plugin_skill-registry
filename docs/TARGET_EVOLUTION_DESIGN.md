# 目标独立 Skills 与工作区启停：交互方案

版本：扩展设计 0.16　日期：2026-11-27　状态：已实施，宿主验收待复核。

本方案基于主程序原有的两个提交：`db92cab`（Target 独立 Skill 列表）、`d23b2c0`（工作区 Target 持久化启用与停用）。延续现有 GitHub Dark 工作台、作用域导航、固定窗口高度、正文滚动和保存前预览，不增加侧栏菜单、操作记录或仪表盘。

交互预览源码归档：[目标能力预览](design/skill-registry-target-evolution.html)。预览使用演示数据，支持清单切换、注释保留与恢复、启停即时保存、YAML 对照与模拟应用。

## 1. 主程序语义及插件差距

| 新能力 | 主程序当前行为 | 插件需补齐 |
| --- | --- | --- |
| 工作区默认清单 | 根级 `skills` 供未声明独立清单的目标继承 | 现有 Skills 清单明确命名为“默认清单” |
| 目标独立清单 | `targets.<id>.skills` 完整替换默认清单，不做并集 | 目标内多选、添加、移除、恢复继承；有效链接按目标各自计算 |
| 独立空清单 | `skills: []` 不创建新链接，目标仍可启用 | 明确展示“独立清单 · 0 个”，不等同于继承或停用 |
| 恢复继承 | 生效配置中没有该目标的 `skills` 字段时继承默认清单 | 插件将完整 `skills` 块注释保留；恢复独立清单时取消注释，不新增原生配置项 |
| 工作区启停 | 注释整个目标块停用，取消外层注释启用；无启停布尔配置字段 | 目标列表保留停用项，并提供启停开关 |
| 预设字段继承 | 工作区仅覆盖声明的字段，路径可来自同名预设 | 分别展示路径来源、Skill 清单来源和启停状态；支持没有本地 path 的稀疏配置 |
| 默认回退 | 显式与自动发现候选为空时先回退，然后过滤停用项；过滤后不再次回退 | 全部停用是正常状态，不暗中启用另一个目标 |
| 增量应用 | 只添加链接；停用、缩减清单都不删除现有链接 | 预览必须说明已有链接保留；停用不表示 Agent 无法读取已有内容 |

源码依据：[配置解析及候选过滤](../../skill-registry/src/lib/config.ts)、[启停、独立清单及应用逻辑](../../skill-registry/src/core/project.ts)、[类型](../../skill-registry/src/types/index.ts)、[回归场景](../../skill-registry/tests/target-skills.test.cjs)。以源码为准，不从旧文档推断能力。

## 2. Agent 目标：主要管理入口

目标列表同时展示启用和停用项，停用后不消失。每项保留名称、完整路径、路径来源、清单模式和成员摘要。每张卡片最右侧固定放置一个“滑块开关 + 已启用 / 已停用文字”的组合控件，合并原先重复的状态徽标和开关。各行控件靠右对齐，位置不随目标名称长度或清单内容变化；卡片标题保留配置入口箭头。

移除“配置 Skills”和行内“编辑路径”按钮，点击卡片任意非开关区域即打开此目标的统一配置弹层，包含部署路径和 Skills 清单。卡片提供轻量悬停高亮、右侧箭头和键盘焦点；使用独立原生按钮承担卡片入口，启停开关作为同级控件，避免交互控件嵌套。点击、空格操作开关直接保存启停状态，不弹确认框，也不会同时打开配置；停用卡片也仍可配置。

滑块绿色、圆钮靠右表示启用，灰色、圆钮靠左表示停用，文字状态只展示一处。操作开关立即切换显示并自动保存，以 160 ms 动画反馈；保存中禁用重复操作，失败后恢复真实状态并在页面内显示错误。底层继续校验配置指纹，不覆盖外部修改。缺失路径时启用会说明需要先补充部署路径，点击卡片可完成配置；系统要求减少动态效果时取消动效。

- **继承默认 · N 个**：跟随当前工作区默认清单。
- **独立清单 · N 个**：只使用此目标保存的清单。
- **独立清单 · 0 个**：保持启用，后续应用不创建新链接。
- **已停用**：后续应用跳过，保存的清单、目录和已有链接保留。

导航“Agent 目标”的计数包含列表中的启用与停用项，页内分别显示两者数量。全局“目标预设”继续维护路径模板，不承载某个工作区的启停和独立清单。

### 统一目标配置弹层

弹层上方配置部署路径，下方配置 Skills 清单。保持路径值不变时，保留原有的路径继承关系，不自动新增工作区路径覆盖；修改路径时与清单一起进入一次变更预览。启停状态由列表中的组合开关控制，保存目标配置不会隐式启用目标。

Skills 清单使用两个单选项：

1. **继承工作区默认清单**：只读展示当前成员与数量，说明默认清单变化会继续生效。
2. **使用独立清单**：使用下方可编辑的自定义成员列表，支持显式空清单。成员增删与整份清单是否生效分开操作。

**自定义技能的新增与移除**：

- 列表显示全部自定义成员，包括已禁用的条目。每行右侧提供“滑块 + 已启用 / 已禁用”状态控件，旁边保留独立的“移除”；启停与增删是不同动作。
- 点击“添加技能”进入中心仓库选择面板，可多选加入；已存在的成员勾选并禁用，避免重复。确认“加入清单”只回到当前目标的编辑草稿，不直接写文件。
- 选择面板的返回、关闭和 Escape 都回到目标配置，保留路径、清单及已有增删草稿；取消本次选取不丢弃整份目标编辑。
- “移除”只移除当前目标自定义清单中的成员，中心内容、工作区默认清单、其他目标和已有链接保留。“清空清单”移除全部成员，保持当前清单使用模式。
- 继承默认时仍可维护下方自定义列表；保存为注释保留，不会自动切换到独立清单。目标停用时编辑也不会重新启用目标。
- 保存预览除完整 YAML 差异外，明确列出待保存的成员增删、清单模式和路径；确认后提交这些草稿。已经通过开关即时保存的成员状态不需要再次确认，取消表单也不会撤销。

首次从继承切到独立且没有注释保留清单时，以空清单开始，不隐式复制默认成员。若存在注释保留清单，则恢复该清单，包括显式空列表。切换选项时保留未提交草稿，取消不写入配置；确认保存时才注释或取消注释。原清单中中心源已缺失的成员仍展示，可移除其引用，不静默丢弃旧成员。

在停用目标中修改清单、复制默认成员、恢复继承，均保持整个目标块的外层注释。只改变本目标的 `skills` 块是否为注释，其他路径、描述、未知字段和用户说明注释保持原样。若目标只剩被注释的清单，仍将目标保留为有效的空映射 `{}`，避免生成 `null`，不等同于移除目标。

点击“预览保存”展示当前工作区、目标、清单模式前后、完整 YAML 差异与影响说明。确认保存后仍需单独应用链接。回到编辑时保留模式和选中成员。

### 单个自定义技能的启用与禁用

逐项开关只决定该成员是否参与当前自定义清单，不改变目标自身启停，也不切换整份清单的继承关系。开关切换后立即保存对应成员状态，不需要点击“预览保存”，也不弹确认框。保存中禁止重复操作，失败后回退并提示错误。路径、清单模式及其他成员增删草稿不随该开关提交。成功保存后只推进本次写入的配置指纹，不吸收外部编辑。关闭或取消表单不会撤销已经保存的开关。新成员若被切换则只将该成员及其状态写入当前已保存目标，其余待添加成员仍是草稿；新目标需先完成创建，才提供即时开关。

- **禁用**：将该条 `- skill-id` 注释为 `# - skill-id`，保留成员、顺序及恢复入口；显示为灰色“已禁用”。
- **启用**：取消该条目的注释，回到原有位置；显示为绿色“已启用”。
- **移除**：删除该成员及其保留条目，不再显示于此自定义清单。移除后重新添加的成员默认启用。
- 添加的新成员默认启用；已经在清单中但被禁用的成员不能重复添加，需回列表开启。复制默认清单作为新起点时，复制的成员均为启用状态。

部分禁用示例：

```yaml
targets:
  codex:
    skills:
      - research
      # - web-testing
```

主程序只读到 `research`。若全部成员都被禁用，必须保留显式空列表：

```yaml
targets:
  codex:
    skills: []
      # - research
      # - web-testing
```

不能把 `skills` 键一起注释，也不能留下被解析为 `null` 的空键；否则会错误恢复默认清单。界面仍显示两个保留成员，应用计划为零，不会自动继承默认技能。目标卡片分别展示有效技能数量与已禁用数量。

整份清单切回继承时，保留每项的启停状态：给整个块增加一层外部注释。恢复独立清单只解除外层注释，单项禁用的内部注释仍在，不会把所有成员重新启用。即使整份清单暂未使用，也允许编辑各成员状态，保存为注释，待独立清单重新使用时生效。

技能详情区分“未纳入清单”和“技能已禁用（注释保留）”；有效总览与应用计划只计算未被注释的条目。中心仓库将这些注释条目标识为保留关联，不当作当前生效引用。

### 继承与恢复：由插件注释和取消注释

采用用户确认的注释思路，不新增 `skills_mode`、`use_custom_skills` 等原生字段，也不要求主程序增加清单模式能力。保留内容直接位于当前工作区 YAML 中，不在插件数据库另存一份清单。

使用独立清单：

```yaml
targets:
  codex:
    skills:
      - research
      - web-testing
```

切换为继承默认清单并保存：

```yaml
targets:
  codex:
    # skills:
    #   - research
    #   - web-testing
```

主程序读取时没有生效的 `targets.codex.skills`，自然沿用现有继承规则；插件读取对应的注释块，在再次选择“使用独立清单”时恢复原成员，保存时取消注释。`skills: []` 同样可注释为 `# skills: []` 并准确恢复，不能误解为继承状态。

变更预览直接展示真实的注释差异，并说明独立清单仍被保留。仅识别同一目标下唯一、结构完整的 `skills` 注释块；存在多个候选或无法解析时不猜测恢复，不自动取消其他用户注释。实现使用 YAML 节点与原文范围定位，不能对整个文件批量增删 `#`。

**兼容与保存**：主程序和插件使用同一份 `ProjectDocument` 读写规则，保存时保留目标、清单和单项技能的注释，不再通过 js-yaml dump 重建项目配置。注释内容直接保存在 YAML 中，不在插件数据库另存。外部编辑器若删除了注释，恢复内容也随之消失；歧义的完整结构注释会报错而非猜测启用。

### 目标启停也使用注释

```yaml
skills: [research]
targets: {}
  # codex:
  #   skills:
  #     - research
  #     # - web-testing
```

停用时给目标块增加一层注释，启用时只移除这一层，内部清单和成员的注释状态保持原样。主程序读取完整且唯一的目标注释块，将目标排除在目录自动发现之外；只要存在明确目标或停用目标，就不会用默认目标兜底。全部停用是正常的零操作结果。

不提供 `enable` / `enabled` 启停配置字段，也不读取、校验或迁移旧字段。目标缺少有效路径时仍可停用及维护清单，启用前必须补充有效路径。

### 启停与缺失路径

自动发现、默认回退目标也可停用；将最小目标映射 `{}` 注释保存在工作区配置中，全局模板不变。未自动发现的预设可经现有“从预设添加”接入；启用与创建目录仍是不同动作，创建目录需明确展示计划。

对于预设已删除且自身没有 path 的停用目标，保留可见，显示“先配置部署路径，再启用目标”。仍允许维护其独立清单；补充路径后才可直接启用。此类配置不能使整个工作区不可读取。

## 3. Skills：默认清单与目标使用总览

侧栏保留单个“Skills”入口，页内提供两个视图，不新增页面菜单：

- **默认清单 N**：编辑根级 `skills`，明确提示只影响继承它的目标；独立清单不随之修改。
- **目标使用总览 N**：只读汇总已启用目标各自的有效清单并去重，逐项列出使用它的目标及“继承 / 独立”来源。点击 Skill 可查看逐目标状态，再进入目标配置。

侧栏去掉原先缺少明确归属的 Skills 数字，数量由页内具名视图表达，避免默认数、目标独有数、停用引用数混成同一个总数。全局中心计数仍为中心 Skill 总数。

默认清单为空时，也可能有目标独立配置的 Skill。此时默认视图显示空状态及“查看目标使用总览”；“预览并应用”按目标有效清单计算，不能因根级 `skills` 为空就禁用。

逐目标详情区分：已链接、待创建、未选用、目标停用、已有链接保留。未选用不记为缺失；独立空清单不渲染成批“未部署”告警。工作区默认移除一个 Skill 时，预览说明其仍可能被独立清单使用。

## 4. 应用预览与配置引用

应用计划按目标分组，使用每个已启用目标的 `target.skills ?? workspace.skills`，不再使用“根级 Skill × 所有目标”的笛卡尔积。每组显示模式、清单数与实际链接；启用但清单为空的目标标为无需创建。

停用目标单列为跳过，保留清单和已有链接的说明。启用目标缩减清单后，多出的原链接显示为保留项；已有的实体冲突、断链、缺失源诊断和安全跳过继续保留。全部目标停用时，预览显示零条期望链接和“不会自动回退”，创建按钮不可用；这是正常无操作结果。

中心仓库的配置引用检查应包含：工作区默认清单、各目标生效独立清单（包括停用项）、全局共享分组。注释保留的独立清单单独标识为“已保留、未生效”的关联，不计入应用计划；移除中心内容时说明可能影响后续恢复。停用只是暂停后续应用，不删除引用。引用仍仅覆盖已接入且可访问的工作区，扫描不完整时继续提示。不能因根级清单中没有某个目标独有 Skill，就把它误认为无人引用并允许无提示移除。

## 5. 交互预览示例

示例为虚构的 `personal-site` 工作区，使用 6 个中心 Skill：

| 目标 | 状态 | 清单 | 初始计划 |
| --- | --- | --- | --- |
| Claude Code | 启用、自动发现 | 继承 3 个默认成员 | 2 条已链接，1 条待创建 |
| Codex | 启用 | 独立 2 个，含一个仅该目标使用的 Skill | 1 条已链接，1 条待创建 |
| Cursor | 启用 | 独立空清单 | 0 条 |
| Windsurf | 停用 | 保留独立 1 个 | 跳过，已有 1 条链接保留 |

总计划为 5 条期望链接、2 条待创建；目标使用总览为 4 个去重后的 Skill。可切换到第二个示例工作区 `notes`，各自配置独立保存。演示状态提供默认清单为空、全部目标停用、停用目标缺失路径等边界情况。

建议讨论时操作：

1. 点击 Codex 卡片 → 配置目标 → 切换继承 / 独立 → 预览并保存，再对照项目 YAML 中的注释变化；关闭弹层并重新打开，验证可恢复原独立清单。
2. 在 Codex 卡片的目标配置中点击“添加技能”，加入中心现有 Skill；逐行移除原成员，确认预览列出具体新增与移除项；再通过逐项滑块禁用成员，核对 YAML 只注释对应列表项，重新打开后可以恢复。清空清单后，目标仍启用，但不再创建新链接。
3. 停用 Codex，再修改清单并恢复继承，确认停用状态没有变化。
4. 编辑默认清单，再查看目标使用总览和应用预览，确认独立清单未被改写。
5. 启用 Windsurf，观察总览和创建计划；在中心仓库查看 `drawio` 的配置引用。
6. 停用全部目标，确认列表仍可操作，应用计划不启用默认目标。

预览只修改演示数据，不读取或写入用户的真实配置、目录和链接。本文件的目标启停、独立清单、成员增删及注释读写已接入插件；真实宿主验收范围见 IMPLEMENTATION.md。
