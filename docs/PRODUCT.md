# SkillRegistory uTools 插件产品设计

版本：已确认方案 0.16　日期：2026-11-27　状态：已进入实施；实现与验收见 [IMPLEMENTATION.md](IMPLEMENTATION.md)

已实施增量：[目标独立 Skills 与注释启停](TARGET_EVOLUTION_DESIGN.md)。目标启停、清单继承 / 独立切换及单项技能开关均通过 YAML 注释保存，细节及最新交互以该增量为准。

## 1. 产品定位

插件名称：**SkillRegistory**。原 CLI 名称与 `.skill-registry` 配置路径继续保持兼容。

把现有 Skill Registry 的文件系统管理能力转化为桌面管理界面：用户选择一个项目文件夹，维护它的 Skill 清单与 Agent 目标，再将中心仓库里的 Skill 以软链提供给各个 Agent。中心内容更新后，指向它的有效软链直接读取最新文件。

“中心仓库”在本产品中指本机统一 Skill 存储目录，不默认等同于一个 Git 远端仓库。目录下可以同时包含来自多个 Git 仓库和本地目录的 Skill。首期管理用户主动接入的文件夹，不扫描整块硬盘，不自动接管所有 Agent 目录。

面向个人自用，保持页面和流程简洁。建议以**工作区 Skills 为默认工作页，通过“工作区 / 全局管理”切换配置作用域**。二者使用同一套文件格式；原 CLI 与插件可以交替使用。

## 2. 现有实现及兼容边界

以下结论以原仓库当前源码为准。历史文档中的数据库、持续分组订阅等描述不能直接作为实施依据。

| 主题 | 当前行为 | 插件设计 |
| --- | --- | --- |
| 技术基础 | TypeScript / Node.js CLI，`src/index.ts` 导出核心函数 | 复用或适配核心业务；插件自身提供本地桥接，默认不依赖已安装的二进制 |
| 全局配置 | 固定为 `~/.skill-registry/global.yaml` | 识别现有文件，编辑仍写回此处 |
| 中心内容 | 默认 `~/.skill-registry/skills`；`registry.path` 可指定其他目录 | 展示解析后的绝对路径；区分配置位置和内容位置 |
| 项目配置 | `<项目>/.skill-registry/config.yaml` | 选项目根目录后读取、初始化和编辑该文件 |
| 存储 | 扫描目录及 `SKILL.md`，没有运行时数据库 | 文件系统是事实来源，不将 uTools 数据库变成第二份 Skill 注册表 |
| 本地导入 | 复制到中心目录 | 明示为“复制导入”；原目录后续修改不会自动传入中心 |
| Git 导入 | 支持仓库根目录及 `git+URL#子目录` | 根目录 Git 可继续更新；旧版子目录导入丢失 `.git`，标为“来源未知或不可更新” |
| 项目应用 | `pull` 仅添加；遇到已存在路径跳过 | 首期保持增量语义，先给变更预览，补充冲突与断链诊断 |
| 删除项目 Skill | 只从配置移除，不删除已部署链接 | 界面提示遗留链接；清理是独立操作 |
| 分组 | 加入项目时展开到 `skills` 并去重；不建立持续关联 | 使用“从分组添加”，展示本次展开清单；后续改组不自动改项目 |
| Target 计算 | 项目显式配置 ∪ 自动探测；同名显式优先；皆空才用默认值 | 标明“项目配置 / 自动发现 / 默认回退”的来源 |
| 自动探测 | 当前按 `path` 首段是否存在判断；`detect` 字段虽已声明却未实际使用 | 首期保留解析规则，不提供无效的 `detect` 编辑开关 |
| Target 空对象 | README 有 `{}` 示例，但当前解析没有补全其 `path` | 插件需做兼容归一化：空对象从同名全局预设取路径；保存前预览显式路径 |

源码依据：[配置](../../skill-registry/src/lib/config.ts)、[存储](../../skill-registry/src/lib/storage.ts)、[项目逻辑](../../skill-registry/src/core/project.ts)、[Skill 导入更新](../../skill-registry/src/core/skill.ts)、[Target 探测](../../skill-registry/src/lib/detect.ts)、[类型](../../skill-registry/src/types/index.ts)。以上相对链接从插件 `docs` 目录指向相邻 CLI 仓库。

## 3. 用户与成功标准

主要用户是同时使用多个 Agent、多个项目的个人开发者。典型任务包括给新项目配一组 Skills、查看某个 Agent 到底能读到哪些 Skills、更新中心资源，以及定位软链未生效的原因。

首期成功标准：

1. 已有用户接入后能直接看到原配置与中心内容，无需迁移文件格式。
2. 从选择已初始化文件夹到添加一个 Skill 并预览应用，在 5 个核心步骤内完成。
3. 保存配置、更新内容、应用链接均有独立结果，用户能分辨每次操作影响哪个位置。
4. 对已有同名实体目录、指向其他位置的软链，默认不覆盖；失败可以定位到具体路径。
5. CLI 或编辑器修改配置后，插件能刷新识别，保存时不会静默覆盖较新的版本。

## 4. 首期范围

### P0：完整的本机管理闭环

| 模块 | 能力 | 主要写入位置 |
| --- | --- | --- |
| 窗口与滚动 | 主窗口尺寸稳定、主内容内部滚动、应用内弹窗正文滚动 | 仅界面状态，不随内容调整宿主高度 |
| 工作区选择器 | 系统原生目录选择、手动路径、最近工作区、接入其他文件夹、家目录项目 | 最近工作区是插件本机偏好；切换不创建项目配置 |
| 设置（工作区） | 统一行式设置：打开目录 / 配置文件、移出最近列表、移除工作区配置 | 本机入口偏好；配置移除使用回收站 |
| 项目 Skill | 查询、搜索、添加中心 Skill、从分组添加、批量移除配置 | 项目 `skills` |
| Agent 目标 | 查询当前生效 Agent、名称与标识、部署路径、来源、链接状态；原生选择目标目录；从预设创建缺失目录并添加；添加、覆盖与删除显式配置 | 项目 `targets` |
| 配置编辑 | 表单与 YAML 两种视图；草稿、差异、校验、保存、重新载入 | 项目或全局 YAML |
| 应用链接 | 只读预检、逐项计划、增量创建、结果与失败重试 | 解析后的 Target 目录 |
| 链接诊断 | 正常、未创建、断链、指向别处、同名实体、遗留链接 | 读取 `lstat` / `readlink`；默认不写入 |
| 中心 Skill | 浏览、搜索、来源筛选、详情、打开文件夹 / `SKILL.md` | 读取中心目录 |
| 中心注册 | 本地目录复制；Git 根目录导入；重复名校验 | 中心目录 |
| 中心更新 | Git 根仓库检查与更新；本地 / 来源未知项给出不可更新原因 | 中心的 Git 工作目录 |
| 中心移除 | 展示已接入项目与分组中的引用；移入回收站 | 中心目录；不默认改写所有项目 |
| 分组管理 | 新建、描述、成员增删、删除、从分组向当前项目添加 | 全局 `groups` |
| 目标预设 | 预设增删改查、默认值、恢复缺失预设 | 全局 `defaults.targets`、`settings.default_target` |
| 设置（全局） | 统一行式设置：打开中心目录 / 全局文件，更改中心目录并预览确认 | 全局 `registry.path` |

项目配置的“删”包含 Skill 引用移除、显式 Target 删除；整份配置文件删除放在工作区左侧列表的“设置”中，以“移入回收站”处理。移出最近项目仅移除入口，不等同于删除配置。

### 后续范围

- P1：受控清理遗留软链、断链修复、中心目录迁移与重连、Git 子目录可追踪更新、多 Skill 批量发现导入、完整 SKILL.md 编辑、中心内容创建模板。
- P1：Windows 目录软链 / junction 的实际兼容验证；在通过验证前不声明完整 Windows 支持。

## 5. 信息架构与页面

```text
SkillRegistory
├─ 工作区
│  ├─ 工作区选择器：只切换或接入文件夹
│  ├─ Skills：本工作区的引用与部署状态
│  ├─ Agent 目标：显式配置与全局预设引用
│  ├─ 项目 YAML：仅当前 config.yaml
│  └─ 设置：目录、入口及配置维护
└─ 全局管理
   ├─ 中心仓库：共享 Skill 内容
   ├─ 共享分组：全局集合
   ├─ 目标预设：共享路径模板与默认值
   └─ 设置：global.yaml 与中心存储路径
```

界面采用简短文案：工作区导航为 Skills、Agent 目标、项目 YAML、设置；全局导航为中心仓库、共享分组、目标预设、设置。“设置”由当前作用域明确归属。

工作区的 Agent 目标页展示实际生效的目标集合及数量，列出 Agent 名称、标识、部署路径、配置来源和已链接 / 待创建 / 冲突 / 源缺失情况。全局目标预设是共享模板集合，不代表当前工作区已启用全部模板。配置生效也不表示对应 Agent 已安装或正在运行。原 CLI 的 Target 概念与 `targets` 数据字段保持兼容。

每个 Agent 的路径旁提供“选择目录…”，直接打开系统原生目录选择框。选中后进入该目标的编辑表单并回填路径，点击“保存目标”才写入当前工作区配置；自动发现或默认回退的目标由此生成工作区显式覆盖，全局预设保持原状。添加、编辑目标的路径输入旁也提供“选择文件夹…”，保留手动填写能力。选择器取消回到原入口，表单草稿保持；取消表单不写配置。选择目标目录不切换工作区，也不立即创建或移动软链。工作区内目录保存为相对路径，外部目录保存为绝对路径并展示实际范围。

两个作用域独立记住当前位置。页面顶部常驻显示本次管理的范围、配置或内容路径及生效说明，弹层再次标明实际写入范围。全局页面不显示当前工作区选择器，避免形成“所有菜单都属于这个项目”的视觉归属。

工作区中可以只读选取全局资源：添加 Skill 只写工作区引用；自动发现 Target 标为“全局预设引用”，通过“覆盖此工作区”生成本地显式配置。编辑全局模板需要明确进入全局管理。全局资源的“添加到工作区…”单独确认目标工作区名、配置路径与新增引用，不直接套用背景页的全局作用域。

工作区选择器只负责切换或接入文件夹。Skills、Agent 目标和项目 YAML 负责工作区内容；两个“设置”均作为普通菜单项置于对应作用域的左侧列表末尾，共用同一套行式布局、打开方式及变更预览流程。工作区中的设置维护目录、配置文件和最近入口；全局管理中的设置维护本机共享中心与全局文件。Skill 引用、Target 和 YAML 内容仍在各自页面编辑。家目录作为项目时属于工作区范围，`~/.skill-registry/config.yaml` 与 `~/.skill-registry/global.yaml` 明确区分。作用域表示配置归属，部署到绝对路径时仍需逐项展示真实写入路径。

uTools 入口为 `SkillRegistory`、`技能管理`；另设文件夹匹配入口“管理此文件夹的 Skills”。打开插件恢复最近项目；新用户先选择文件夹或查看中心仓库。传入文件夹只定位该根目录，不递归扫描。

两个设置页的操作协议一致：只读项通过“打开目录 / 打开文件”查看；可更改项先输入或选择参数，再预览作用位置、变更前后和影响；已有明确参数的维护动作直接预览。确认后留在对应设置页更新状态，取消保持原设置，失败保留输入并允许重试。目录选择共用系统原生接口；选择工作区与更改全局中心分别回到各自上下文，不交叉写入。各页只展示实际可用项，不为对称增加全局删除或重置功能。

## 6. 关键流程与明确语义

### 6.1 接入已有项目或创建配置

1. 点击“选择文件夹…”打开系统原生目录选择框，仅允许单选目录；手动路径作为折叠备选。取消时保持原工作区与输入不变。确认后校验目录、归一化真实路径、去重，并展示最终配置路径。
2. 文件存在则解析和校验；缺失则显示“此工作区尚未初始化”，用户点击初始化后，在弹层确认将创建的完整配置路径与 `skills: []`。
3. 确认后创建 `<根目录>/.skill-registry/config.yaml`；成功进入空清单，提供“添加第一个 Skill”和“查看初始配置”。创建不包含拉取中心内容或部署链接，取消保持未初始化状态。
4. 落盘前再次检查文件是否出现，采用仅新建的写入方式，禁止覆盖已有配置；写入失败保留上下文和重试入口。
5. 全局配置缺失时先引导初始化中心；不在浏览文件夹时自动生成文件。
6. 目录不可访问、YAML 损坏、中心不可读分别提供错误与修复入口，保留原始文件。

家目录也作为项目处理：`~/.skill-registry/config.yaml`；只有用户明确接入家目录时才操作家目录目标。

### 6.2 编辑配置并应用

1. 用户在项目中添加、移除 Skill 或编辑 Target，产生未保存草稿。
2. “保存配置”展示配置差异并只写 YAML。保存成功后单独显示链接待应用状态。
3. “预览并应用”基于**已保存配置**扫描 Skill × 最终 Target。若有未保存草稿，先选择保存或返回编辑。
4. 计划逐项分成：创建、已正确链接、源缺失、断链、冲突、遗留。冲突默认跳过，其余可创建项可继续；清楚显示结果会部分完成。
5. 用户执行后只创建计划中的缺失链接，不覆盖实体或其他链接，不删除遗留项。当前页面或弹层显示成功 / 跳过 / 失败数量与失败原因，并允许就地重试；关闭后不保存历史。

例如 6 个 Skill、2 个 Target 共 12 条期望链接：9 条正常、2 条待创建、1 条与本地目录冲突。执行后为 11 条正常、1 条冲突；界面不能显示“全部同步完成”。

### 6.3 中心内容导入与更新

- 本地：选择一个含 `SKILL.md` 的目录 → 校验目录名与重复项 → 预览中心位置 → 复制导入。明确注明“原目录之后的修改不会自动同步”。
- Git：输入仓库 URL → 校验并读取候选 Skill → 预览注册名与中心位置 → 导入。P0 仅完整根仓库支持后续 Git 更新。
- Git 子目录：保留原 CLI 格式认知，P0 显示暂不支持可追踪导入并说明可先本地复制；P1 才引入来源元数据，不把旧副本伪装为 Git 仓库。
- 更新：先检查 Git 可用性、远端、工作区变更与快进条件；离线或分叉给出失败原因，脏工作区阻止更新并引导打开目录处理，不自动 stash / reset。更新完成后，现有软链直接读到新内容，无需再次部署。
- “检查更新”必须实际获取远端信息后才可显示“有更新”；未检查显示“尚未检查”，不能由本地时间推断。

### 6.4 删除的四种含义

| 操作 | 影响 | 确认方式 |
| --- | --- | --- |
| 从项目配置移除 | 删除清单引用，现有文件与链接仍存在 | 差异确认，提示会产生遗留链接 |
| 移出最近工作区 | 删除插件本机快捷入口；当前工作区继续使用，配置与文件保留 | 轻确认，再次选择文件夹可重新加入 |
| 移除项目配置 | 将项目 YAML 移入回收站，已有部署保留 | 显示具体路径，二次确认 |
| 从中心仓库移除 | 中心内容进入回收站，已有链接可能断裂 | 显示已知引用，输入注册名确认；引用存在时默认阻止 |

引用数只能覆盖已接入、仍可访问的项目与全局分组。界面必须标为“已接入项目引用”；存在不可访问项目时标记扫描不完整，不能显示“无任何引用”。允许用户明确理解影响后强制移除，但不自动修改所有项目。

### 6.5 中心目录切换

P0 仅切换到现有目录。预检目录、读取能力、Skill 数量及已知链接影响；确认只更改 `registry.path`。旧软链仍指向旧位置，旧内容保留；不会因为改配置自动改写软链。切换后的应用预览会将指向旧目录的链接标为冲突。复制迁移、批量重连放到 P1 专门流程。

## 7. 数据与可靠性要求

### 兼容的数据模型

```yaml
# <项目>/.skill-registry/config.yaml
skills:
  - handoff
  - research
targets:
  claude-code:
    path: .claude/skills
  codex:
    path: .codex/skills
```

```yaml
# ~/.skill-registry/global.yaml
registry:
  path: ~/.skill-registry/skills
defaults:
  targets:
    claude-code:
      path: .claude/skills
    codex:
      path: .codex/skills
groups:
  daily:
    description: 日常开发
    skills: [handoff, research]
settings:
  default_target: claude-code
```

注册名以中心子目录名为稳定 ID；`SKILL.md` 的 `name` 用作展示名。二者不一致时同时展示，不能把展示名当作文件路径。P0 不提供注册名重命名，以免影响现有软链。

插件只额外保存项目别名、最近目录和界面偏好。项目状态和引用数按文件系统重新计算。暂不向既有 YAML 增加插件专有字段；既有 `groups`、未知字段在编辑保存时保留。表单编辑需保留 YAML 注释与未知键；不支持安全往返的复杂 YAML 切换为原文编辑，并说明原因。

### 写入与任务规则

- 写入前对比加载时内容指纹；外部改动时保留草稿，提供重新载入与差异合并。写入采用同目录临时文件替换和备份；串行化插件自己的任务。原 CLI 不共享插件锁，因此不承诺跨进程事务，执行前再次校验。
- 预览标记配置指纹与相关路径状态；执行前重新检查 `lstat` / `readlink`，过期时重新生成计划，不复用陈旧的覆盖判断。
- Skill 名拒绝路径分隔符、`..`、绝对路径；完整路径归一化。显式绝对 Target 与 `~/` 目标允许使用，但需展示作用域；不能把其当成项目内目录。
- 新链接不得覆盖实体文件或外部软链。中心目录自身或其父目录不能被设为危险 Target；检查源目录与目标目录重叠、循环及别名路径。
- 有效性区分实体、断链、链接目标；不能只用 `existsSync` 判断存在。
- UI 不执行任意 shell 字符串；Git 使用参数数组。本地内容预览不执行 Skill 内的脚本，Markdown 禁用原始可执行 HTML。
- 长任务在当前页面或弹层显示进度与结果，不设置历史页面，不持久保存执行明细。离开页面不中断正在写入的单项步骤；取消只停止后续条目。重进插件后重新扫描真实状态。
- Git 更新使用现有系统 Git 与凭据；缺少 Git 时其他本地管理能力仍然可用。

## 8. 实施方案建议

建议采用 TypeScript + React + Vite，preload 输出 CommonJS。界面通过明确的业务接口调用配置、存储与链接服务，禁止直接暴露 `fs` 或任意进程执行。核心逻辑可基于原 TypeScript 模块适配并随插件打包；不要求用户额外安装 CLI，不通过工作目录全局切换实现项目选择。

uTools 官方当前文档描述了 Web 界面 + preload 的运行架构；preload 可以调用 Node.js 并使用 CommonJS。以 uTools 8+ 为建议基线，实施前应在用户实际版本中验证。官方当前运行环境与原 CLI 的 Node 18+ 要求相容，但依赖打包仍需验证。[运行架构](https://www.u-tools.cn/docs/development/plugin-architecture.html)、[preload](https://www.u-tools.cn/docs/development/preload.html)。

插件可通过入口指令、文件夹匹配进入；初始高度只在进入时按宿主约束设置，切换作用域、页面或打开应用内弹窗不得按内容调用高度调整。主内容超出时内部滚动，弹窗固定题头与底部操作、只滚动正文；用户主动调整窗口时再适配可用尺寸。设计稿固定 700 px 高。横向布局必须适配宿主宽度，不能假定总有 1024 像素。删除到回收站、打开文件和文件夹可使用宿主系统接口。[入口配置](https://www.u-tools.cn/docs/development/plugin-json.html)、[窗口接口](https://www.u-tools.cn/docs/api-reference/window.html)、[系统接口](https://www.u-tools.cn/docs/api-reference/system.html)。

实施目录：`src/` 界面、`bridge/` 本地桥接、`core/` 适配后的业务、`shared/` 接口类型、`public/` 插件声明和资源、`tests/` 隔离验证、`docs/` 设计资料。全部位于 `utools-plugin_skill-registry/`；`dist/` 为构建后可导入的插件。

目录选择接入 uTools 的 `showOpenDialog`，设置 `properties: ["openDirectory"]`，不启用文件选择或多选。`defaultPath` 使用已展开为绝对路径的当前工作区目录；`buttonLabel` 为“选择文件夹”。接口确认后返回路径数组，取消返回 `undefined`，两者分别处理。读取权限或目录校验失败时保留原工作区并显示原因，不更新最近列表。此接口仅负责选目录；选择后才读取项目配置，缺失时进入已有初始化引导。[原生目录选择接口](https://www.u-tools.cn/docs/api-reference/system.html)。

Agent 目标目录复用同一原生接口，增加 `showHiddenFiles` 以便选择 `.claude`、`.codex` 等隐藏目录。默认定位当前目标解析后的目录；目录不存在时回退到最近可访问的父目录，最终回退到工作区。返回值只回填目标路径草稿，不能进入工作区切换或中心目录更改分支；校验失败保留草稿并显示原因。不存在的部署目录仍可手动填写，可在“从预设添加”流程确认创建预设目录，或待应用阶段按计划创建。

### 从预设创建并添加工作区目标

在工作区“Agent 目标”页提供“从预设添加”，从当前全局 `defaults.targets` 读取候选项，包含原 CLI 预置及用户维护的模板。相对路径基于当前工作区展开；`~/` 与绝对路径展示真实目录及“工作区外”标记。被用户移除的全局预设不会在此流程自动恢复。

1. 打开时检查目录状态，不创建文件。每项显示名称、标识、模板路径、真实目录与状态，支持多选，默认不勾选任何项。
2. 缺失目录可选，包括已作为默认回退或自动发现生效的目标；确认后创建目录并写入显式配置。已配置同一路径但目录缺失时允许补建，保留其未知字段。
3. 已有目录可选并添加为显式目标，内容保持原状；已添加且目录存在的目标不可重复选择。同名目标已使用自定义路径时不可覆盖；实体文件占位、危险路径等项禁用并说明原因。
4. 点击“预览添加”展示待创建 / 已存在目录、完整写入路径与 YAML 差异；“返回编辑”保留选择，取消不产生目录或配置变更。
5. 点击“创建目录并添加”（全部目录已存在时为“添加到工作区”）后，重新校验工作区与全局配置指纹、目录及软链解析。只创建所选目录，保存当前工作区配置，全局模板保持原状。Skill 链接仍需独立“预览并应用”。
6. 保存失败时撤回本次创建且仍为空的目录，不移除预先存在的目录，不递归删除。若新目录已有内容或身份变化则保留并列出位置。配置冲突或预设变化时重新载入列表后再预览。

## 9. 验收场景

| 场景 | 应满足的结果 |
| --- | --- |
| 未初始化工作区 | 选择目录不创建文件；取消初始化保持原状；确认后仅创建空配置，并可继续添加首个 Skill |
| 初始化失败或配置已出现 | 显示原因并允许重试；不覆盖初始化期间由外部创建的配置 |
| 系统目录选择 | 主入口打开原生单目录选择框；取消不切换、不更改最近列表；手动路径仍可用 |
| 工作区切换 | 已初始化与未初始化目录的清单和状态分别保留，中心资源继续共享 |
| Agent 目标展示 | 当前工作区列出生效 Agent 名称、标识、路径、来源及链接状态；数量独立于全局模板数；新目标与覆盖结果在此可见 |
| 从预设添加目标 | 多选缺失目录 → 预览 → 确认创建并添加；默认回退可补建，已有内容保留，自定义覆盖禁用；取消无写入；保存失败仅回退本次空目录；全局配置与 Skill 链接不随之改动 |
| Agent 目录选择 | 列表和目标表单均可选目录；选中只回填草稿，确认保存才改当前工作区；取消保留配置和表单输入；自动发现目标保存为本地覆盖，全局预设不变 |
| 导航文案 | 两边均显示“设置”；全局模板为“目标预设”；工作区实际目标为“Agent 目标”，作用域清晰 |
| 工作区入口职责 | 选择器仅切换文件夹；工作区设置与全局设置使用同一结构和交互；Skills、Agent 目标和 YAML 各自编辑内容 |
| 设置交互一致 | 两边的打开方式、编辑与预览、取消和结果反馈一致；提交后留在当前设置页，更新范围正确 |
| 目录选择上下文 | 更改全局中心时选择目录不切换当前工作区；取消选择保留编辑输入，取消整个更改不写配置 |
| 已有项目与中心接入 | 不迁移目录，不丢未知字段，正确显示配置与内容路径 |
| 添加中心 Skill | 保存 YAML 后才改变清单；应用后创建缺失链接 |
| 中心文件更新 | 两个项目已有链接读到同一份新内容，无需复制 |
| 本地复制导入 | 修改原始导入目录不影响中心副本，界面有明确说明 |
| 重复执行应用 | 第二次无重复创建，无已有文件变化 |
| 同名实体 / 外部链接 | 保留原物；输出具体冲突路径与跳过结果 |
| 从配置移除 Skill | 配置生效，链接保留并可诊断为遗留 |
| 缺失源与断链 | 分别显示原因，不标记为正常或静默跳过 |
| 分组编辑后 | 已经展开到项目的 Skill 不自动增删 |
| 自动 Target 删除 | 删除显式项后仍命中自动探测时继续显示，并说明原因 |
| 外部同时改 YAML | 保存被拦截，草稿保留，可对照外部版本 |
| Git 离线 / 脏工作区 | 有原因与重试 / 打开入口，不破坏原内容 |
| 中心删除 | 引用扫描范围可见，有二次确认，能从回收站恢复内容 |
| 中心路径切换 | 明示旧链接保持原指向，不声称已完成迁移 |
| 作用域隔离 | 全局页面无工作区选择器，工作区菜单无全局管理项；每页与写入弹层标注所属范围 |
| 预设引用与覆盖 | 全局修改可影响引用该模板的工作区；工作区显式覆盖不修改全局预设 |
| 跨作用域添加 | 先展示全局来源与目标工作区配置，确认后只新增该工作区引用 |
| 窗口高度稳定 | 工作区与全局的所有页面及长弹窗保持同一外框高度；超出内容通过内部滚动访问，弹窗底部操作始终可见 |
| 滚动位置 | 同页更新与弹窗开关保留位置；进入新页面 / 作用域时从顶部开始 |
| 小窗口与键盘 | 关键动作无裁切，详情可单独打开，弹层可 Escape 关闭并恢复焦点 |

## 10. 讨论时需要确定的选择

1. **核心集成方式**：建议随插件打包 TypeScript 核心；也可指定仅包装原 CLI，但会增加安装与版本配套成本。
2. **首期平台**：建议 macOS 先验证，Windows 作为紧随版本；如要求同批上线，需把 junction、路径及权限验证纳入首期。
3. **链接清理强度**：建议首期仅诊断与增量创建；如必须完整移除部署，可将“仅清理指向当前中心的托管链接”提升到 P0，另行定义归属证明与确认流程。

当前按已确认的建议实施：内置 TypeScript 核心、macOS 先行、首期只诊断与增量创建链接。后续范围继续独立安排。
