# 实现与宿主验收

更新：2026-11-27。依据产品文档 0.15 与同版本设计稿实施。源代码与可导入的构建产物均位于本插件目录。

## 加载

1. Node.js 20.19+ 执行 `npm ci`。
2. 执行 `npm test`、`npm run build`。
3. uTools 开发者工具中导入 `dist/plugin.json`，搜索 `SkillRegistory`。
4. 也可使用文件夹匹配入口。入口只定位文件夹，不自动创建配置或链接。

`dist/preload.js` 为 CommonJS，第三方依赖已打包；`dist/assets` 为离线界面资源。宿主初始高度由 `pluginSetting.height: 700` 设置，页面切换不调用高度调整。界面使用实际可用高度与内部滚动。目标运行环境为官方文档列出的 Node.js 20.19.1；工程测试可使用更高版本 Node。

## 功能与结构

| 文件 | 职责 |
| --- | --- |
| `shared/types.ts` | 界面与本地桥接的明确业务请求 / 返回结构 |
| `bridge/preload.ts` | uTools 入口、目录选择、偏好存储、系统打开及 Electron 回收站；不暴露通用 fs / shell 执行 |
| `core/config.ts` | YAML AST 往返、注释保留、空目标兼容、指纹检查、临时文件替换与单份备份 |
| `core/paths.ts` | 路径展开、真实目录解析、中心与目标重叠检查 |
| `core/links.ts` | 显式配置与自动发现并集、默认回退、链接诊断与遗留项 |
| `core/target-directories.ts` | 工作区预设目录状态、按选择创建、保存失败时仅回退本次空目录 |
| `core/registry.ts` | 中心扫描、稳定注册名与 SKILL.md 展示名、只读内容解析 |
| `core/git.ts` | 参数数组调用系统 Git、真实 fetch、脏工作区与分叉检查、只允许安全快进 |
| `core/service.ts` | 串行任务、预览令牌、保存、导入、引用检查、应用与取消后续条目 |
| `src/App.tsx` | 两种作用域、固定布局、工作区与全局页面、YAML 草稿和导航保护 |
| `src/dialogs.tsx` | 统一弹层、变更前后预览、文件夹选择、错误重试与合并 |

工作区配置仍为 `<工作区>/.skill-registry/config.yaml`，全局配置仍为 `~/.skill-registry/global.yaml`。插件偏好仅存最近工作区和导航位置，不复制注册表或保存操作历史。注释与未知字段通过 YAML AST 保留；锚点、别名及复杂键转到原文编辑。损坏 YAML 也可校验后修复，保存前保留原始版本的 `.bak`。

原生目录选择仅单选；Agent 目标选择显示隐藏目录，取消保留输入，选中只回填草稿。列表中直接选择目录也需经表单与差异确认后保存。更改全局中心仅改配置，旧内容与软链保持原状。手动路径可指定尚未创建的目标目录。

工作区 Agent 目标提供“从预设添加”，读取当前全局预设并检查目录，默认不勾选。预览绑定工作区和全局配置指纹以及目录真实路径；确认后创建所选缺失目录并写入显式目标，不应用 Skill 链接。已有同名自定义路径禁用，已有目录内容保留；保存失败仅按目录身份回退本次创建且为空的目录，有内容或身份变化时保留并报告。

应用前后均检查配置与路径状态。只创建缺失链接，不覆盖已有实体、外部链接或断链；移除引用不清理已部署链接。重叠或循环目标拒绝应用。执行结果在当前弹层显示成功 / 跳过 / 失败，支持重新预览后重试。

本地复制导入会移除 Git 元数据，后续不跟随原目录。Git 导入仅支持根仓库包含 SKILL.md 的完整仓库；预览阶段准备临时副本，取消会清理。旧版子目录副本无 Git 元数据时按本地 / 来源未知展示。Git 更新不自动 stash、reset 或合并分叉，不运行仓库 hooks。

## 自动验证

`npm test` 使用临时家目录、临时工作区与本地 Git 远端，不访问个人全局配置，不联网下载 Skill，也不调用真实回收站。

- 核心：初始化互斥、注释与未知字段、空目标归一化、配置冲突、原文修复、目标解析、共享软链、增量幂等、实体 / 外链 / 断链 / 缺失源、陈旧预览、目录别名、预设目录批量创建 / 显式修复 / 自定义路径保护 / 外部路径 / 取消 / 过期预览 / 失败回退与新出现文件保留、导入副本、引用阻止删除、中心切换、Git fetch / 快进与脏工作区保护。
- React：初始化 → 添加引用 → 单独应用真实软链；目标目录选择和取消；预设多选、目录预览、返回保留选择、创建确认及禁用状态；外部刷新不替换表单指纹；未保存导航与手动合并；两种设置与中心目录选择的上下文隔离。
- 桥接：将 preload 编译为 CommonJS 后在隔离上下文执行，核对宿主方法、文件夹入口、错误返回以及回收站失败不降级为永久删除。

以上不等同于真实 uTools 图形宿主验收。测试替代了原生弹窗 / 回收站接口；布局由 CSS 约束与交互测试检查，未在本轮声称完成真实宿主截图验证。

## 界面裁切复核（2026-11-27）

本次修复共用样式中的三类问题：

- 外置焦点轮廓被 `overflow` 滚动容器裁掉：输入框、文本域、选择框、按钮与搜索容器统一使用内置轮廓；保留键盘可见焦点，不移除滚动或扩大窗口。
- 无空格的长工作区名称、分组描述等文本横向溢出：为界面文本继承可断行规则。
- 分组成员的长标识标签不换行：成员标签最大宽度限制为容器宽度，允许断行显示完整名称。

使用实际 React 组件与源码样式，在浏览器中配合隔离演示数据复现并验证。覆盖工作区目标、全局目标预设、分组、Git / 本地导入、中心目录、添加 Skill 搜索、预设长列表和全局 YAML 编辑器；检查 1000 × 700、580 × 700、320 × 700 和 1000 × 440 的布局。长列表和编辑器只在正文滚动，底部操作区保持在窗口内。额外使用 90 字符无空格工作区名称、120 字符成员标识及长描述检查边界。

复核后，320 px 窗口中的分组卡片 `scrollWidth` 与 `clientWidth` 均为 277 px（修复前分别为 2395 / 277 px），弹窗长工作区名称均为 278 px（修复前分别为 772 / 278 px）。这些浏览器检查使用模拟宿主桥接，不等同于 uTools 原生宿主验收。

## 宿主验收步骤

建议创建一个临时工作区和一个含 SKILL.md 的本地 Skill 目录，通过界面完成以下检查：

1. 导入构建后的 manifest，确认关键词和单文件夹匹配入口均可打开；宽窄窗口均可访问全部页面。
2. 工作区选择、中心目录更改与 Agent 目标选择都打开系统原生目录窗口；目标选择能看到 `.claude` 等隐藏目录。取消保持上下文。
3. 未初始化工作区只在确认后生成空配置。添加引用后文件发生变化；单独应用后才出现链接。
4. 在另一个编辑器修改 YAML；返回插件刷新后保留本地草稿，保存冲突可比较与合并。
5. 在目标下创建同名普通目录和其他软链，应用时均保留；移除引用后链接保留并显示遗留状态。
6. 用临时数据验收系统打开及回收站。回收站错误时保留原文件；从回收站恢复后刷新可重新识别。
7. 切换全局 / 工作区、打开长弹层，窗口高度不随内容变化；正文滚动且弹层操作区保持可见。关闭弹层或同页刷新不重置主滚动位置。
8. Git 检查使用用户已有系统 Git 与凭据。离线、脏工作区和分叉给出原因；安全更新后已有软链可读到新内容。

跨进程写入不承诺事务：插件会在预览、保存、创建链接前重新检查，但原 CLI 不共享插件任务队列。Windows、完整 SKILL.md 编辑、遗留链接清理、Git 子目录可追踪导入及中心迁移仍属于产品文档的后续范围。

宿主接口依据：[plugin.json](https://www.u-tools.cn/docs/development/plugin-json.html)、[preload](https://www.u-tools.cn/docs/development/preload.html)、[原生目录窗口](https://www.u-tools.cn/docs/api-reference/system.html)、[Electron shell](https://www.electronjs.org/docs/latest/api/shell)。


## 0.16 目标配置增量

已接入目标块、独立清单块、成员三层注释读写。目标右侧开关直接保存，无确认弹窗；保存中阻止重复提交，失败时恢复状态并显示行外错误；卡片打开统一配置，支持 Finder 路径选择、继承 / 独立切换、成员新增移除与即时开关。成员开关只提交对应条目，保留其他草稿；保存后推进表单指纹，失败回退并保留草稿，取消表单不撤销已保存的开关。全部成员停用保持显式空清单，全部目标停用不触发兜底。路径未改动时保留继承。应用计划及中心引用扫描覆盖目标独有成员和注释保留成员。

`core/project-yaml.ts` 与主程序 `src/lib/project-yaml.ts` 保持一致。目标启停只依据注释，没有旧 `enable` / `enabled` 字段的读取、校验或迁移逻辑。跨应用回归使用临时 HOME 和工作区执行真实 CLI，验证相互保存后可恢复注释状态。CLI 不提供 target enable/disable 命令；启停由插件完成。自动化验证不等同于真实 uTools 宿主验收；目标开关、目录选择和长列表滚动需要在宿主内冷启动复核。
