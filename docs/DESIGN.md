# SkillRegistory 界面与交互设计

版本：实现稿 0.16　日期：2026-11-27

已实施增量：[目标独立 Skills 与注释启停的交互方案](TARGET_EVOLUTION_DESIGN.md)。Agent 目标卡片、统一配置弹层和 Skills 双视图以此增量为准。

## 1. 设计方向

采用紧凑的桌面工具布局：左侧为工作区和全局导航，主区域为清单，宽窗口右侧提供详情。弱化装饰，让 Skill 名称、作用路径、当前状态和下一步操作最醒目。配色采用 GitHub Dark 风格：近黑灰主背景、略亮的内容表面、细灰边框、蓝色强调与绿色主按钮。固定使用深色，不随宿主系统切换为浅色。

工作台作为已选方案。左侧顶部先选择“工作区”或“全局管理”，再呈现该作用域自己的上下文与导航。窄窗口沿用同一套作用域结构，将导航移到顶部。

## 2. 作用域与导航

### 选择独立作用域

推荐在导航顶部使用“工作区 / 全局管理”双入口，并切换整组导航与上下文。只给原有菜单加分隔标题，仍会让全局页面位于工作区选择器下面，不能充分消除归属误解。

```text
工作区
├─ 当前工作区选择器（仅切换）
├─ Skills
├─ Agent 目标
├─ 项目 YAML
└─ 设置

全局管理
├─ 中心仓库
├─ 共享分组
├─ 目标预设
└─ 设置
```

全局侧栏在作用域切换下直接显示功能导航，取消重复的共享配置说明块，不为其保留空位。

两个作用域分别记住上次页面。全局页面不显示工作区选择器；项目名只在明确的“添加到工作区”流程中作为目标出现。切回工作区时恢复原工作区与当前视图。

### 导航文案与 Agent 目标

两个作用域的设置入口及页面标题均简写为“设置”，通过当前作用域、面包屑和配置路径区分。全局模板入口称“目标预设”；工作区中实际生效的目标入口称“Agent 目标”，替代原“部署目录”名称。

“Agent 目标”页面展示当前工作区的最终目标集合，每项包含 Agent 名称、标识、解析后的部署路径、来源与当前 Skill 的链接状态。导航计数按当前生效目标计算，不使用全局预设数量。来源区分工作区显式配置、全局预设自动发现与默认回退；全局预设引用可以在此工作区单独覆盖。

默认示例为 2 个 Agent 目标、6 个 Skills：Claude Code 的 6 条链接正常；Codex 为 3 条正常、2 条待创建、1 处冲突。页面不将配置生效标为 Agent 已安装或正在运行。新初始化但没有 Skill 时，展示默认目标并提示等待添加 Skill；未初始化工作区继续引导初始化。

全局“目标预设”维护可供复用的路径模板；工作区“Agent 目标”体现显式配置与自动发现的并集，两者均空时才使用默认目标。界面命名调整不改变原 `targets` 配置格式。

每个目标的路径旁提供“选择目录…”，可直接唤起 macOS 系统目录选择框，无需先进入编辑。选中后回到目标表单，回填部署路径，点击“保存目标”后生效；添加、编辑表单的路径输入旁也提供同一选择入口。工作区内路径保存为相对路径，外部目录保留绝对路径。原生窗口显示隐藏目录，便于选取 `.claude/skills`、`.codex/skills` 等位置；当前目录不存在时从可访问父目录打开，手动输入仍可指定待创建目录。

从列表取消选择返回列表；从表单取消选择返回表单并保留 Agent 标识与已输入路径。选中目录后取消表单，不改变已保存目标。自动发现和默认回退的目标保存后变为“工作区显式配置”，不修改全局模板。选择目标目录始终保留当前工作区与中心目录，路径保存也不自动创建或移动现有链接。

### 从预设添加目标

“Agent 目标”页右上角保留“添加目标”作为手动输入入口，增加主按钮“从预设添加”。使用现有工作区作用域弹层，不增加侧栏菜单，也不调整主窗口高度。

选择弹层以紧凑复选列表展示所有当前全局预设，每行包含 Agent 名称 / 标识、模板路径、展开后的实际目录以及状态。默认无选中项，底部显示“已选 N 个 · 待创建 M 个目录”。长列表只在弹层正文滚动，取消和预览按钮保持可见。

| 状态 | 列表表现 | 确认结果 |
| --- | --- | --- |
| 目录待创建 | 可选；默认回退也可选 | 创建缺失目录并保存为工作区显式目标 |
| 已配置目标 · 目录待创建 | 可选 | 补建目录，保留原目标配置字段 |
| 目录已存在 · 添加为显式目标 | 可选 | 保留目录内容，仅添加显式配置 |
| 已添加到工作区 | 禁用 | 避免重复添加 |
| 已配置自定义路径 | 禁用并显示当前自定义路径 | 不覆盖工作区已有选择 |
| 路径不可用 | 禁用并说明原因 | 不写入 |

`~/`、绝对路径和解析后位于工作区外的目录带“工作区外”标记，不默认选中。空预设列表引导前往全局“目标预设”。

“预览添加”进入统一变更预览：先列出目标目录与“将创建 / 已存在 · 保留内容”，再列出 YAML 变更前后；确认文案为“创建目录并添加”，全部已存在时为“添加到工作区”。返回编辑保留选择，取消无写入。成功后留在 Agent 目标页更新目标与状态，提示可继续预览并应用链接。冲突或目录创建失败在弹层内显示原因，提供“重新载入预设”，不会转入丢失目录创建语义的纯 YAML 合并流程。

### 工作区切换与统一设置

点击当前工作区只打开切换器：列出最近工作区与初始化状态，主入口“选择文件夹…”通过系统原生目录选择框接入其他文件夹；“手动输入路径”默认折叠，按需展开。选择一个目录后关闭切换器，进入该工作区。切换器不承载初始化、查看 YAML、打开目录、移出入口或配置删除操作。

原生选择框仅允许选择一个目录。macOS 使用系统目录打开面板；确认后校验路径并读取 SkillRegistory 配置。取消返回切换器，保留原工作区和已输入的路径；只有成功接入的目录才加入最近列表。目录是否已初始化的判断发生在选择之后，初始化仍需用户明确发起。

Skills、Agent 目标和项目 YAML 保持为三个内容入口。两个作用域中的“设置”作为普通导航项，分别排在对应左侧列表末尾，使用相同图标、间距与选中态；设置入口与其他列表项连续排列，窄窗口沿用相同顺序。

两个设置页共用同一套页面、设置行和变更预览结构：

| 结构 | 设置（工作区） | 设置（全局） |
| --- | --- | --- |
| 位置与配置 | 工作区目录、项目配置文件 | 中心目录、全局配置文件 |
| 查看动作 | 打开目录、打开配置文件 | 打开目录、打开配置文件 |
| 可更改项 | 最近列表入口、工作区配置维护 | 中心目录路径 |
| 维护操作 | 移出列表、将工作区配置移入回收站 | 按实际能力展示，不补造维护项 |
| 生效范围 | 当前工作区 | 本机所有工作区共享 |

每一行统一为“名称 + 当前值 / 路径 + 右侧操作”，按需要附一行影响说明。设置页不额外放置功能介绍卡片。工作区目录为只读位置，切换文件夹始终通过工作区选择器；配置文件的“打开文件”使用系统默认程序，与项目 YAML 页中的内容编辑分开。

统一交互规则：

1. 查看：点击“打开目录 / 打开文件”，采用相同的系统打开方式，无额外确认。
2. 更改：需要参数时先打开编辑弹层，例如更改中心目录；文本路径和系统目录选择可互用。校验通过后进入“预览变更”。已有明确参数的维护动作直接进入同一个预览。
3. 预览：统一展示作用域、作用位置、变更前、变更后和影响说明；确认按钮使用“保存路径”“确认移出”“移入回收站”等具体动作。
4. 取消：已保存设置保持原状；取消目录选择回到原编辑弹层，并保留输入。
5. 完成：留在对应设置页，更新行内状态并显示简短结果。移除工作区配置后，设置页显示“尚未创建配置”，用户可明确前往 Skills 页重新初始化。
6. 失败：在原编辑或预览位置显示原因，保留当前输入和重试入口。

两页按各自的实际设置项展示内容，不为版式对称增加无用操作。工作区设置不编辑 Skill 引用、Target 或 YAML；未初始化状态的创建流程仍在 Skills 页完成。

### 页面、资源来源与写入位置

| 操作 | 所属范围 | 写入位置 | 影响 |
| --- | --- | --- | --- |
| 工作区 Skill 增删 | 工作区 | 当前目录的 `config.yaml` | 此工作区引用清单 |
| 工作区 Target 覆盖 | 工作区 | 当前目录的 `config.yaml` | 此工作区显式路径，全局模板不变 |
| 添加、更新、移除中心 Skill | 全局 | 中心存储目录 | 引用该内容的多个工作区 |
| 编辑共享分组 | 全局 | `global.yaml` 的 `groups` | 共享集合；已展开的工作区清单不变 |
| 编辑目标预设 | 全局 | `global.yaml` 的 `defaults.targets` | 引用该模板的工作区；已有显式路径不变 |
| 修改中心目录 | 全局 | `global.yaml` 的 `registry.path` | 本机共享中心配置，旧链接需另行处理 |
| 从中心或分组添加到工作区 | 工作区 | 确认的目标 `config.yaml` | 只添加工作区引用，不修改全局资源 |

每页在内容顶部常驻作用域条：工作区显示名称、配置路径和“仅此工作区”；全局显示“本机共享”、全局配置或中心目录，以及具体的共享影响。弹层也独立标明本次操作所属范围，避免继承背景页造成误解。

作用域标签描述配置归属。部署到显式绝对路径或 `~/` 路径时，预览另行标记项目外路径，不能以“工作区”标签暗示文件写入一定局限于项目目录。将家目录作为项目接入时，它仍是一个工作区，其 `config.yaml` 与全局 `global.yaml` 分别管理。

### 引用与覆盖

- 工作区 Skill 详情将中心内容标为“全局内容 · 只读”。在工作区只改引用；“进入全局中心”明确切换作用域。
- 自动发现或默认回退的 Target 显示“全局预设引用”，保留具体发现方式。使用“覆盖此工作区”生成本地显式路径；“查看目标预设”进入全局管理。
- 显式 Target 显示“工作区显式配置”，编辑按钮为“编辑目标”。
- 工作区“从全局中心添加”在当前上下文内只读挑选；不因资源来自全局而切换整页作用域。
- 全局“添加到工作区…”单独展示“读取全局资源 → 写入目标工作区”，列出工作区名和配置路径，确认按钮带目标名称。保留共享资源的管理上下文。
- 全局更新弹层提示已知引用工作区数量；保存 Target 时使用“保存预设”或“保存目标”，弹层同时显示实际写入的配置文件与作用域。

## 3. 页面与入口规格

| 页面 | 主体 | 主操作 | 次要动作 |
| --- | --- | --- | --- |
| 工作区选择器 | 最近工作区与其他文件夹 | 系统选择文件夹 | 切换最近工作区、展开手动路径 |
| 设置（工作区） | 统一行式设置：工作区目录、配置文件和维护操作 | 打开目录 / 文件 | 预览并移出列表、移除配置 |
| 工作区 Skills | 清单与链接状态；选中项的来源及 Target 详情 | 预览并应用 | 添加 Skill、从配置移除 |
| Agent 目标 | 当前工作区生效的 Agent、标识、完整路径、来源与链接状态 | 从预设添加 | 添加目标、选择目录、编辑目标、覆盖此工作区、查看目标预设 |
| 项目 YAML | 配置文本、校验状态、未保存指示 | 保存配置 | 放弃修改、重新载入 |
| 中心仓库 | Skill 清单、Git / 本地筛选、内容预览 | 注册 Skill | 检查更新、更新选中项、打开、移除 |
| Skill 分组 | 集合与成员；显示展开加入说明 | 新建分组 | 编辑成员、添加到当前项目、删除 |
| 目标预设 | 预设名称、路径和默认标识 | 新建预设 | 编辑、设为默认、移除、恢复缺失项 |
| 设置（全局） | 统一行式设置：中心目录与全局配置文件 | 打开目录 / 文件 | 更改目录 → 预览变更 → 保存路径 |

## 4. 首屏样例与关键状态

设计稿的所有名称、路径、时间、远端、引用数都是演示数据。默认项目 `personal-site` 配置 6 个 Skill，2 个 Target；12 条期望链接里 9 条正常、2 条待创建、1 条与同名实体目录冲突。中心共有 8 个 Skill。默认选择 `frontend-design`，其 Codex 链接待创建。

页头作用域条显示工作区名称与完整配置路径。Skill 页的高优先级动作是“应用到此工作区”；当前状态用一行摘要和警示条表达，不增加无意义的数据仪表盘。

列表右侧的操作必须明确：“从配置移除”“从中心移除”“更新内容”不可共用“删除”或“同步”的模糊文案。详情中的链接使用 `Skill → Target` 的关系显示中心与目的路径。

## 5. 交互规范

### 导航与选择

- 项目选择器显示别名与路径，重复接入同一真实目录去重。
- 作用域切换发生在导航第一层，各自只显示自己的菜单。全局管理不保留工作区选择器；跨范围操作在弹层明确目标工作区。
- 宽度足够时选中清单项显示侧栏详情；较窄时以“查看详情”进入独立内容面板，提供返回。
- 搜索仅作用于当前清单，匹配注册名和描述；没有结果时显示清除搜索，不能以空白代替。

### 未初始化工作区的引导

1. 工作区选择器列出文件夹名称、完整路径及“已初始化 / 未初始化”状态；新目录默认通过系统原生弹窗选择，也可展开手动路径输入。选中未初始化目录只切换上下文，不自动创建配置。
2. 主区域显示空状态“此工作区尚未初始化”，主按钮为“初始化 SkillRegistory”，并提供“选择其他工作区”。没有配置时，不展示添加 Skill 或应用链接等后续动作；项目 YAML 与 Agent 目标入口暂不可用。
3. 点击初始化，弹层明确“工作区范围”、将创建的 `<根目录>/.skill-registry/config.yaml` 和初始内容 `skills: []`，用户可以取消。
4. 确认“创建配置”后显示短暂进度，禁用重复提交。成功后回到工作区空清单，显示“工作区初始化完成”，提供“添加第一个 Skill”和“查看初始配置”。初始化本身不部署任何链接。
5. 创建失败在原弹层展示路径与原因，保留重试入口；已有配置则直接载入或提示，不覆盖。
6. 已初始化与未初始化工作区可来回切换，各自保留 Skill 清单与路径。全局中心始终是同一份共享资源。

独立示例 `design/initialization-preview.html` 默认选中未初始化的 `new-project`。也可从主设计稿的工作区选择器选择 `new-project` 体验同一流程。设计调节项“初始化结果”支持“成功 / 首次失败”，用于检查错误与重试状态；全部为页面内模拟。

### 添加 Skill

- 项目内添加：从中心勾选 → 展示增量清单 → 保存配置。已经存在的 Skill 不重复加入。
- 中心注册：Git / 本地两个入口；显示最终目录、注册名校验、复制语义与可更新条件。
- 所有保存表单都在字段附近显示错误，不在失败后关闭弹层。

### 预览与部分完成

- 预览分项显示动作、Skill、Target 和原因；可创建项默认执行，冲突项默认跳过且不可直接覆盖。
- “创建 2 个链接，跳过 1 处冲突”比“确定”更准确。
- 执行后刷新为 11 条有效 / 1 处冲突；保留处理冲突入口，避免通用成功 Toast 掩盖部分完成。
- 进度与结果显示在当前页面或弹层，失败可就地重试；关闭后不保留历史，也不增加专用页面。

### 未保存与外部修改

- 未保存状态常驻编辑区，并提供保存与放弃；切换项目时询问如何处理草稿。
- 外部文件改变后显示差异，保留本地输入；不自动将草稿覆盖到新版本。
- 表单与 YAML 是同一份草稿的两种视图；语法损坏时阻止表单保存。

### Target 与分组

- “自动发现”项显示只读路径与来源；可转为显式配置后编辑。移除显式配置不等于禁用自动发现。
- 不设计“关闭自动发现”的虚假开关，旧 schema 没有 exclusion 机制。
- 分组操作文案固定为“从分组添加”；预览实际新增 Skills 和去重数，不显示“订阅”。

### 删除

- 项目引用移除说明保留现有链接。
- 中心移除弹层显示已知引用、扫描范围、实际目录；确认输入使用注册名。
- 回收站不可用时停在错误状态，不静默改为永久删除。

## 6. 视觉系统

| 元素 | 规范 |
| --- | --- |
| 焦点与内容边界 | 输入框、文本域、选择框、按钮和搜索容器的焦点边框绘制在自身边界内，避免被滚动容器裁切；长名称和描述可断行，分组成员标签限制在容器宽度内并换行 |

## 7. 尺寸与可访问性

- 设计评审宽度 1024 px；实际开发依据宿主可用宽度响应，窄窗口继续显示同一作用域切换。
- 930 px 以下详情按需进入；760 px 以下主导航移到顶部；小于 520 px 时操作区换行，路径与表单纵向排列。
- 设计预览支持 320 px 无横向溢出。插件实际不以手机端为交付目标。
- 设计稿主窗口固定为 700 px 高；切换工作区 / 全局、页面、筛选、列表密度以及打开弹窗，均不按内容改变窗口高度。实际插件填满宿主可用区域，只响应用户主动调整窗口尺寸。
- 宿主顶栏、侧栏和底部状态栏位于固定窗口内；主内容区域纵向滚动。列表、详情、设置和 YAML 内容超出时由主区域容纳，不撑高外框。
- 应用内弹窗的最大高度受窗口可用区域约束，标题与底部操作区保持可见，只有正文、长列表或表单区域滚动。原生目录选择框由系统管理，不改变主窗口高度。
- 相同页面更新、打开或关闭弹窗时保留主区域滚动位置；切换页面 / 作用域或进入窄窗口独立详情视图时从顶部开始。相同弹窗内容更新保留正文滚动位置。
- 纵向滚动区域预留稳定的滚动条空间，避免内容增减引起横向跳动；窄窗口继续使用同一固定高度与内部滚动规则。
- 键盘可完成切页、选项、输入、确认和取消。弹层自动聚焦、限制焦点范围，Escape 关闭并恢复触发位置。
- 动态结果使用礼貌播报，校验错误使用 alert；不以颜色作为唯一信息。

## 8. 设计稿覆盖与评审路径

打开 `design/preview.html` 体验完整工作台，或打开 `design/initialization-preview.html` 体验初始化。两者均为同一套工作台交互：

1. 选择 `new-project` → 初始化 → 确认文件路径和空清单 → 创建完成 → 添加第一个 Skill；也可取消或体验失败重试。
2. 切回已初始化的 `personal-site` → 应用到此工作区 → 创建可执行链接 → 查看保留的冲突。
3. 工作区选择器只体验文件夹切换。分别从对应左侧列表进入工作区与全局范围的“设置”，对照相同的行式布局、打开方式、变更预览、取消和成功后的状态更新；全局目录更改也可使用系统目录选择。
4. 项目添加 Skill → 勾选中心项目 → 保存；再从配置移除一项，观察“现有链接保留”。
5. 从工作区导航进入“Agent 目标”，点击路径旁“选择目录…” → 选择样例目录 → 回填路径 → 保存目标；对照取消选择、取消表单和全局预设保持不变的结果。添加新目标时，也可在表单内选目录。再进入“项目 YAML”，核对新增的显式路径。
6. 中心仓库 → 搜索 / 来源筛选 → 查看内容 → 注册弹层 → Git / 本地切换。
7. 选中 Git Skill 更新；选中本地 Skill 查看不可 Git 更新原因；尝试中心移除确认。
8. 分组编辑与展开添加、Target 预设管理、中心路径预检。
9. 切换到“全局管理”，检查全局页面与弹层的共享影响提示，再切回原工作区；窄窗口仍保留作用域入口。

高度验收：依次切换 Skills、中心仓库、分组、预设和两种设置，外框高度保持 700 px；打开包含长列表的添加 Skill / 编辑分组弹窗，正文可滚动，取消和保存按钮保持可见，关闭后主区域位置不跳动。

设计稿里的目录弹窗为交互示意，使用样例目录；实际插件将调用系统原生目录选择，不以网页自绘面板替代。

演示交互用于核对页面关系、文案与状态，不是插件功能实现：没有 uTools 桥接、磁盘访问、Git 调用或真实 YAML 解析器。YAML 演示仅支持稿内列出的简化结构；工程实施必须使用完整解析器并满足产品文档的往返保留要求。
